# Соглашения HTTP API

Этот документ определяет правила именования публичных HTTP-маршрутов, endpoint’ов и контрактов SupportFlow. Они делают API предсказуемым для разработчиков, генераторов клиентов и тестов, но не заменяют обсуждение конкретного пользовательского сценария.

## Маршруты

- Маршруты начинаются с общего префикса `/api`.
- Сегменты пишутся на английском языке в нижнем регистре.
- Коллекции называются существительными во множественном числе: `/api/organizations`, `/api/tickets`.
- Составные сегменты разделяются дефисом: `/api/support-groups`.
- Параметр маршрута явно называет ресурс: `{organizationId}`, а не абстрактный `{id}`.
- Каноническая форма маршрута не заканчивается завершающим `/`: `/api/organizations`.
- Обычные операции создания, чтения, изменения и удаления выражаются HTTP-методом, поэтому глагол в URL не дублируется.

Например:

```text
POST  /api/organizations
GET   /api/organizations/{organizationId}
PATCH /api/organizations/{organizationId}
```

Отдельный глагольный сегмент допустим для доменной команды, которую неудобно и неясно представлять обычным CRUD-изменением. Например, закрытие обращения может быть выражено как `POST /api/tickets/{ticketId}/close`. Такое исключение сначала рассматривается как часть контракта конкретного сценария: REST-подобный стиль не должен скрывать смысл бизнес-операции.

ASP.NET Core может сопоставить запрос и с вариантом, содержащим завершающий `/`, но документация, тестовые клиенты и генерируемые ссылки используют одну каноническую форму. Клиент не должен рассчитывать на поддержку альтернативного написания пути.

Версия пока не включается в URL. Условия появления версий и стратегия обратной совместимости зафиксированы в [ADR-0004](../adr/0004-defer-api-versioning.md).

## Имена endpoint’ов и operationId

Каждый публичный endpoint получает явное имя через `WithName`. Используется PascalCase по схеме «действие + ресурс»:

- `CreateOrganization`;
- `GetOrganization`;
- `ListOrganizations`;
- `UpdateOrganization`.

Имя должно быть регистрозависимым и глобально уникальным в приложении. ASP.NET Core использует его для адресации endpoint’а при генерации ссылок, а встроенный генератор OpenAPI — как `operationId`.

Стабильный `operationId` важен для генераторов API-клиентов: они могут превратить его в имя вызываемого метода. Его изменение рассматривается как изменение публичного контракта, даже если HTTP-метод и путь остались прежними.

Имена endpoint’ов располагаются рядом с регистрацией соответствующего endpoint’а. Общий каталог строковых констант заранее не создаётся. Константа появляется только тогда, когда одно имя действительно требуется нескольким участкам production-кода. Contract-тест намеренно сравнивает OpenAPI с ожидаемой строкой, а не с той же production-константой: иначе одновременное ошибочное изменение константы и сгенерированного документа осталось бы незамеченным.

## Теги OpenAPI

Тег называет группу связанных endpoint’ов и записывается в PascalCase. Для ресурса используется форма во множественном числе:

- `Organizations`;
- `Tickets`;
- `Identity` — имя функциональной области, а не отдельного ресурса.

Если тег относится ко всем endpoint’ам группы, он задаётся один раз на `MapGroup`. Это устраняет повторение и не позволяет новым endpoint’ам случайно выпасть из своей группы в OpenAPI.

## Контракты запросов и ответов

HTTP-контракты принадлежат конкретному пользовательскому сценарию и именуются по схеме:

- `<Operation>Request` для входных данных;
- `<Operation>Response` для успешного ответа.

Например, сценарий создания организации использует `CreateOrganizationRequest` и `CreateOrganizationResponse`.

Контрактные типы не заменяются доменными сущностями или EF Core-моделями. Разделение позволяет независимо развивать внешний JSON-контракт, правила предметной области и схему хранения, а также не раскрывает клиенту внутренние поля.

Не следует заранее вводить универсальные `Dto`, `BaseRequest`, `BaseResponse` или один тип для нескольких несвязанных операций. Общий контракт выделяется только после появления реального одинакового смысла, а не только совпадающего набора полей.

Имена свойств в C# записываются в PascalCase. В JSON используется стандартная web-настройка ASP.NET Core с camelCase. Изменение имени, типа, обязательности или смысла поля оценивается с точки зрения обратной совместимости.

## Проверка соглашений

OpenAPI является машиночитаемым представлением публичного контракта. Contract-тесты закрепляют значимые значения, включая:

- HTTP-метод и путь;
- `operationId`;
- тег;
- имена схем запроса и ответа;
- заявленные коды и форматы ответов.

Тесты не должны повторять всю сгенерированную спецификацию целиком: иначе безопасное обновление генератора создаст много шума. Проверяются только значения, на которые рассчитывают клиенты и которые команда намерена поддерживать.

Текущий `POST /api/organizations` уже соответствует этим правилам. Новые endpoint’ы должны следовать им либо явно объяснять причину исключения.
